## 5) Findings, Decisions, Assumptions
- **Finding:** An older `sim/` prototype exists, but its booking panel returns a hardcoded seat and does not prove interval-safe seat reuse. The new folder borrowed the useful Mapbox/data shape and replaced the booking core with a tested interval-calendar engine.
- **Finding:** The enclosing git state is broken with `fatal: bad object HEAD`; this folder has its own local git repo for continuity.
- **Decision:** Use a deterministic booking core with seat calendars keyed by segment intervals. A seat is available for `[originIndex, destinationIndex)` only when no existing booking interval overlaps it.
- **Decision:** Generated route records keep all HSR OD records and expose 280 simulation-ready routes. Intermediate stop lists are generated from geographically plausible stations between endpoints and labeled as simulation-derived.
- **Decision:** Replaced first-record route slicing with stratified route sampling by macro-corridor and origin province. The generated route set now exposes 1,200 simulation-ready routes.
- **Decision:** The simulation engine now creates 1,500 scheduled train services from the route set, initializes movement state immediately, returns full lightweight `bookingOptions`, and caps visualized trains to active/near-term/completed services for browser performance.
- **Decision:** Use a tiny `scripts/serve-static.cjs` server for the in-app browser because detached Vite processes are killed by the desktop tool environment. The stable browser URL remains `http://127.0.0.1:5174/`.
- **Decision:** Model realistic operating variance with station dwell, hub/platform pressure, deterministic weather/dispatch delay, no-show probability, and no-show seat release after departure.
- **Decision:** Move simulation execution to a browser Web Worker. The UI no longer owns the `SimulationEngine`; it talks to `SimulationWorkerClient`, which posts `quoteTrip`, `bookTrip`, `setSpeed`, and `snapshot` messages to the worker.
- **Decision:** The current rolling-stock quota is 554 seats per train: 10 business seats, 204 first-class seats, and 340 second-class seats from the configured eight-car layout. With 1,500 trains over 1,200 routes, the current generated schedule averages 1.25 trains per route.
- **Decision:** Use HOTOSM rail-corridor point matching to generate segment polylines. Some segments still fall back to station chords when the local OSM rail subset lacks nearby usable geometry, but the train interpolation now follows rail-corridor polylines for matched segments.
- **Decision:** The scheduling model now treats January 1 as an explicit surge calendar day, keeps a 24-hour operating clock, guarantees at least 2 trains per route per day, and scales additional route services by route frequency, hub endpoints, distance, corridor importance, weekend/holiday/peak-season multipliers, and capacity pressure.
- **Decision:** The high-volume booking path uses cached class pools, segment-load indexes, fast capacity checks, and fast silent allocation for preload/live demand so passenger volume can rise sharply without making every quote scan and sort all seats unnecessarily.
- **Decision:** Keep the production default at 6,000 scheduled trains instead of 8,400. The 8,400-train probe produced 3.82M passengers and 1,322 active trains before optimization, but the final 6,000-train setting still gives 6.62x passengers, 663 active trains, and much safer browser responsiveness.
- **Decision:** Browser worker initialization now uses progressive background demand preload. The UI receives an initial network snapshot quickly, then passenger/revenue totals stream upward as the worker books synthetic demand in chunks.
- **Decision:** Restore the supplied public Mapbox token and style as browser fallbacks while continuing to reject the secret `sk.` token in `./init.sh`.
- **Decision:** For the full-year request, keep detailed seat calendars in the rolling active-day Web Worker and persist the 365-day network plan as OceanBase aggregate facts. This satisfies uncapped annual train/passenger/revenue totals without forcing millions of train objects and seat calendars into the browser heap.
- **Decision:** Use PyMySQL and OceanBase's MySQL-compatible interface for ETL because the local OceanBase Desktop tenant is already reachable as MySQL 5.7-compatible OceanBase at `127.0.0.1:2881`.
- **Decision:** Use CPU multiprocessing for annual planning. The workload is branch-heavy and database-I/O-heavy; Mapbox remains GPU/WebGL-backed for rendering, while compute GPU offload is deferred until there is a regular numeric kernel worth moving to WebGPU.
- **Assumption:** Local CSV route records provide real origin/destination train services but not full stop-by-stop timetables. This remains true until a more authoritative timetable source is added.

## 6) Issues, Mistakes, Recoveries
- **Issue:** Prior prototype hardcoded booking confirmation. **Root cause:** UI was implemented before a real booking API. **Fix:** Exposed `quoteTrip`, `bookTrip`, and `cancelBooking` from the engine and routed UI bookings through them. **Guardrail:** `tests/engine.test.mjs` fails if booking does not mutate segment availability.
- **Issue:** The parent git repository is unusable. **Root cause:** `/Users/rogerlin/.git` reports `fatal: bad object HEAD`. **Fix:** Initialize and commit inside `ChinaHSR_Simulation` rather than attempting to repair unrelated parent history.
- **Issue:** User observed that most routes were not being travelled and trains clustered on a few corridors. **Root cause:** `prepare-data.cjs` selected the first 280 eligible route records and `SimulationEngine` only instantiated the first 120 routes. **Fix:** Added diversified route selection, 1,500 scheduled services, immediate movement-state initialization, full booking options, and dashboard coverage charts. **Guardrail:** `tests/dataDiversity.test.mjs` and the engine scale test fail if coverage collapses.
- **Issue:** User reported `ERR_CONNECTION_REFUSED` for `127.0.0.1:5174`. **Root cause:** No server was listening; detached Vite child processes exit in this environment and the prior port was not pinned by default. **Fix:** Pin Vite dev/preview to 5174, add a static production server, and submit it via `launchctl` under `com.codex.china-hsr-simulation`. **Guardrail:** `curl -I http://127.0.0.1:5174/` must return HTTP 200 before ending.
- **Issue:** User observed frozen revenue/passenger/delay metrics. **Root cause:** demand was mostly preloaded at startup and delay metrics used whole-schedule aggregates. **Fix:** added live demand sales every simulation ticks and active-train delay metrics. **Guardrail:** live-demand regression checks revenue/passenger totals increase after ticks.
- **Issue:** User observed trains travelling over water. **Root cause:** positions used straight interpolation between station coordinates. **Fix:** generated HOTOSM rail-corridor segment polylines and interpolate train coordinates along those polylines when available. **Guardrail:** data diversity test requires at least 45% rail-matched segments and detailed rail polylines.
